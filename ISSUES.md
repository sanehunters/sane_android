# ISSUES.md — how the GitHub issue tracker mirrors the methodology

> The methodology lives in files (`START.md`, `cards/`, `checklist/`). The issue tracker is a **projection**
> of those files, regenerated by `python3 scripts/gh-sync.py`, so that a model or a human who only has the
> issue list still has a complete, ordered work queue. Issues never carry content that is not in the files.

## 1. The standing issues (never closed)

| Kind | Label | One per | Body generated from |
|---|---|---|---|
| **Start here** | `type: methodology` | repository | `START.md` §1–§4 |
| **Phase playbook** `P0`…`P9` | `type: playbook`, `phase: n …` | phase | `START.md` §4 table row + the phase's gate predicate (`scripts/gate.py`) |
| **Domain battery** `D01`…`D28` | `type: checklist`, `domain: Dnn`, `phase: …`, `area: …`, `am: …` | domain | `cards/Dnn.md` (crux, applicability probe, triage order, the item table) |
| **Doctrine reference** | `type: methodology` | doctrine doc | the first section of each `docs/*.md` |

All standing issues carry `do-not-close`. A GitHub Action reopens any that is closed and comments why.
Progress is **never** recorded by closing them.

## 2. The per-engagement issues (opened and closed)

| Kind | Template | Label | Opened when | Closed when |
|---|---|---|---|---|
| 🎯 Engagement | `02-engagement.yml` | `type: engagement` | P0 | the assessment is complete (`scripts/gate.py done` open) |
| 🐞 Finding | `01-finding.yml` | `type: finding`, `sev: …`, `am: …`, `domain: …` | a finding is confirmed (P7) | reported and accepted/declined |
| ✅ Ruled out | `03-ruled-out.yml` | `type: ruled-out`, `domain: …` | a domain or component sweep comes back clean with a mechanism | immediately (it is a record) |
| 📋 Checklist gap | `04-checklist-gap.yml` | `type: gap`, `domain: …` | the checklist missed or mis-stated something | merged into a chapter |
| 🔧 Audit finding | — | `type: audit` | a defect in the methodology itself is found | fixed in a commit |

Finding and ruled-out issues are optional mirrors of the engagement folder — the folder is the record of
truth; the issues exist for people who live in GitHub.

## 3. Labels

| Family | Values | Purpose |
|---|---|---|
| `type:` | methodology · playbook · checklist · engagement · finding · ruled-out · gap · audit | what the issue is |
| `phase:` | 0 scope · 1 lab · 2 acquire · 3 inventory · 4 static · 5 ipc · 6 network · 7 chain · 8 evidence · 9 report | where in the state machine |
| `domain:` | D01 … D28 | the one filter a model actually uses: `--label "domain: D07"` |
| `area:` | recon · manifest-perms · ipc · deeplink-webview · storage-crypto · auth-session · network-api · native-supplychain · cloud-sdk · cross-platform · privacy · resilience · platform · payments · push-messaging · device-oem · ai-llm · tooling-reporting | coarse grouping |
| `am:` | remote · one-click · zero-perm-app · one-perm-app · cross-account · network · sdk · backend · physical | attacker model family |
| `sev:` | critical · high · medium · low · informational | findings only |
| `needs-` | device · root · mitm · frida · two-accounts · otp-route · payment-sandbox · kyc · physical-device · oem-image · source · staging | what the battery or finding cannot proceed without |
| flags | `do-not-close` · `high-yield` · `graveyard` · `static-only` · `blocked-by-operator` · `good-first-hunt` · `legacy` | routing |

## 4. Milestones

`M0`…`M9` mirror the phases and group the standing issues for navigation. They are **not** a progress bar
(standing issues never close); per-engagement progress is `scripts/state.py` on the engagement folder.

## 5. Commands

```bash
GH_TOKEN=… python3 scripts/gh-sync.py --dry-run        # show what would be created/updated
GH_TOKEN=… python3 scripts/gh-sync.py                   # labels, milestones, standing issues (idempotent)
GH_TOKEN=… python3 scripts/gh-sync.py --audit docs/08-senior-audit-2026-10.md   # one issue per open audit defect
```

Without the `gh` CLI the script uses the REST API directly; it needs `repo` scope. Issue bodies are
regenerated from the files, so edit the files, never the issues.
